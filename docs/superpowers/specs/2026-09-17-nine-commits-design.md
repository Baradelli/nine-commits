# Nine Commits — Design

**Date:** 2026-09-17
**Status:** Approved (design). Implementation not started.
**Owner:** Vitor Baradelli (`@Baradelli`)

---

## 1. Goal

Build a technical blog that establishes the author as someone who genuinely
understands AI agents — not someone who read about them.

The blog is the proof; LinkedIn is the megaphone. Every post ships with a
companion LinkedIn post and a cover image.

**Audience:** working developers evaluating whether to build agents themselves,
and hiring managers / peers scanning for signal on LinkedIn.

**Language:** all published content in English. (Study notes stay in the
author's Obsidian vault and are not the source of truth for this site.)

### The core idea

> The author does not write *about* agents. The author **builds a real agent**,
> records real execution traces — including the ones that failed — and the site
> replays those traces step by step.

Every interactive demo on the site is a run that actually happened on the
author's machine, tied to a real commit in this repository. This is the
property that content generated by a language model cannot have, and it is the
foundation of everything below.

### Non-goals

- Not a course. It does not try to teach the reader to build an agent
  end-to-end; it argues a thesis per post and shows evidence.
- Not a live LLM playground. No reader-supplied API keys, no backend.
- Not a translation or summary of the source course.

## 3. Content architecture

### 3.1 The series

**Nine Commits** — one agent, built in nine commits.

Each post maps to a real git tag in this repository. The reader can
`git checkout v3-the-loop` and run exactly the agent described in that post.
The interactive demo on the page replays traces recorded from that commit.

This triple binding — **post ↔ commit ↔ trace** — is the series' structural
argument.

### 3.2 The nine posts

Deliberately reordered relative to the source course. The course introduces
evals before the agent loop; the narrative is stronger when the reader sees the
agent *alive* before being asked to care about testing it.

| # | Tag | Post | Thesis | Interactive demo |
|---|---|---|---|---|
| 1 | `v1-not-an-agent` | An LLM Is Not an Agent | Agent = LLM + actions + loop. Without the loop it is a chatbot. | Same task, chatbot vs agent, side by side |
| 2 | `v2-hands` | Giving It Hands | A tool's *description* is a prompt. Bad description, wrong tool. | Reader edits the description, sees the model's choice change |
| 3 | `v3-the-loop` | The Loop | History, tool results, stop conditions. | Frame-by-frame step-through of the message array |
| 4 | `v4-does-it-work` | But Does It Work? | Single-turn evals test decisions, not prose. | Eval grid, pass/fail per case |
| 5 | `v5-moving-target` | Judging a Moving Target | LLM-as-judge over non-deterministic output. | Same run, different judge criteria |
| 6 | `v6-four-operations` | Four Operations | Filesystem: four primitives, and why they are enough. | Agent reading and editing files |
| 7 | `v7-context` | Context Is the Real Constraint | Web search blows the window; compaction is the fix. | Token budget bar filling, compaction firing |
| 8 | `v8-shell` | Shell Access, and Why That's Terrifying | Full power means full risk. | A dangerous command being blocked |
| 9 | `v9-hitl` | The Human in the Loop | Runtime approvals. | Reader approves or denies; two recorded branches |

### 3.3 Post spine

Every post follows the same five beats:

1. **Thesis** — a claim the reader can disagree with
2. **What I built** — the actual change at this commit
3. **What broke** — mandatory. A real failure, with the trace that shows it
4. **The demo** — the interactive replay
5. **The commit** — link to the tag and the diff

The "what broke" section is not decoration. It is the evidence that the work
was actually done, and it is the section a language model cannot fabricate
convincingly.

### 3.4 Post folder

Everything a post needs, colocated and versioned in one commit:

```
site/src/content/posts/03-the-loop/
├── index.mdx          # the post
├── linkedin.md        # the LinkedIn companion post
├── cover.png          # generated, committed (1200x627)
├── cover-prompt.md    # prompt for a generative-image alternative
└── trace.json         # normalized + redacted execution trace
```

Some posts carry several traces (`trace-a.json`, `trace-b.json`) for the
compare-style demos.

### 3.5 LinkedIn companion

One `linkedin.md` per post. Structure: hook line, three to five short lines,
one counterintuitive claim, link to the post. Stored in the repo so the text is
versioned alongside the content it promotes.

### 3.6 Cover image — two tracks

Both tracks ship for every post.

**Track 1 — generated (`cover.png`).** An HTML/JSX template rendered to PNG at
1200x627 via Satori + resvg-js. Consistent series identity, post number, title,
and a fragment of the real trace as background texture. Generated by
`npm run covers`, **committed to the repo** so the author can grab the file
directly without running CI.

**Track 2 — prompt (`cover-prompt.md`).** A written prompt for a generative
image model, kept in the repo for the author to edit and regenerate art when a
typographic cover is not wanted.

Rationale for defaulting to track 1: typographic covers outperform generic AI
art in a technical LinkedIn feed, and a generated cover is reproducible and
reviewable in a diff.

## 4. Technical architecture

### 4.1 Repository layout

Public monorepo with npm workspaces. The agent that produces traces and the
site that replays them live in the same commit.

```
nine-commits/
├── agent/                       # the author's TypeScript agent
│   ├── src/
│   ├── evals/
│   ├── traces/                  # raw recorder output (gitignored)
│   └── package.json
├── site/                        # Astro
│   ├── src/
│   │   ├── content/posts/<slug>/
│   │   ├── components/
│   │   ├── layouts/
│   │   └── pages/
│   ├── astro.config.mjs
│   └── package.json
├── tools/
│   ├── record-trace.ts          # raw -> site format, with redaction
│   └── make-covers.ts           # cover generation
├── docs/superpowers/specs/
├── package.json                 # workspaces
└── README.md                    # attribution to Scott Moss's course
```

The agent's stack mirrors the course so the author's study notes stay
applicable: `ai` SDK, `@ai-sdk/openai`, `zod`, `ink` for the TUI, Laminar
(`@lmnr-ai/lmnr`) for evals.

### 4.2 The trace system

One format, recorded once, replayed everywhere. A trace is an ordered list of
frames; each frame is a snapshot of agent state.

```ts
type Frame =
  | { type: 'user';        content: string }
  | { type: 'tool_call';   id: string; name: string; args: unknown }
  | { type: 'tool_result'; id: string; ok: boolean; result: unknown }
  | { type: 'assistant';   content: string }
  | { type: 'compaction';  before: number; after: number; summary: string }
  | { type: 'approval';    tool: string; decision: 'allow' | 'deny' }

type Trace = {
  id: string
  commit: string              // tag of the agent that produced it
  model: string
  task: string
  outcome: 'success' | 'failure' | 'partial'
  tokens: number[]            // per-frame budget, drives the post 7 meter
  frames: Frame[]
}
```

**Recording.** The agent gains a `--record` flag that writes raw runs to
`agent/traces/`. The author runs real tasks; the recorder dumps them.

**Normalization and redaction.** `tools/record-trace.ts` converts raw output to
the schema above and redacts before anything reaches `site/`:

- absolute paths containing the user's home directory
- environment variable values
- anything matching API-key shapes (`sk-`, bearer tokens)
- any path or string listed in `tools/redact.config.ts`, an explicit
  author-maintained deny list for project-specific secrets

This is not optional. Real agent traces routinely leak machine paths and file
contents, and this repository is public.

**Validation.** The schema is enforced with zod at build time. An invalid or
missing trace fails the build — never a silently empty demo in production.

### 4.3 Components

The engineering bet is to refuse a bespoke demo per post.

- **`<TracePlayer trace={...} />`** — the single island. Step, play, scrub,
  reset; renders any `Frame` variant. All nine posts use it. What varies per
  post is configuration and skin, not new code.
- **`<TraceCompare traces={[...]} />`** — a thin wrapper over the player for
  posts 2, 4 and 5, where the reader switches one variable (tool description,
  judge criteria) and sees a different recorded trace.
- **`<ScrollScene>`** — scrollytelling helper built on IntersectionObserver
  plus SVG transforms. No animation library. Honors
  `prefers-reduced-motion`.

**Island framework:** Preact (~3kb), not React (~45kb). Same JSX the author
already knows, and it keeps the performance argument that the site itself is
making.

**Progressive enhancement:** with JavaScript disabled, `<noscript>` renders the
trace as a static transcript. The argument of a post never depends on the demo
running.

### 4.4 Cover pipeline

`tools/make-covers.ts` renders a JSX template through Satori to SVG, then
resvg-js to PNG at 1200x627. Run locally via `npm run covers`; output is
committed.

Satori over a headless-browser screenshot: no browser dependency, fast, and
deterministic output that diffs cleanly.

### 4.5 Deploy

GitHub Actions workflow building `site/` only and publishing with
`actions/deploy-pages`. The `agent/` workspace is never deployed — its value is
being readable in the public repo.

Astro is configured with `site: 'https://baradelli.github.io'` and
`base: '/nine-commits'`.

### 4.6 Data flow

```
author runs agent --record
        |
        v
agent/traces/*.json          (raw, gitignored)
        |
        |  tools/record-trace.ts  -> normalize + redact
        v
site/src/content/posts/<slug>/trace.json   (committed)
        |
        |  zod validation at build
        v
<TracePlayer /> island  ->  reader steps through a real run
```

## 5. Error handling

| Situation | Behavior |
|---|---|
| Missing or malformed trace | Build fails loudly with the offending path |
| Frontmatter missing required field | Build fails (Astro content collection schema) |
| Unknown `Frame` variant at runtime | Player renders the raw JSON rather than crashing |
| JavaScript disabled or island fails | `<noscript>` static transcript |
| A committed trace still matches a secret pattern after redaction | Build fails; the trace never ships |

---

## 6. Testing

- Trace schema and post frontmatter validated at build time (zod + content
  collections).
- Playwright smoke test: every post page renders, the player advances at least
  one frame, zero console errors.

Deliberately cut for now (YAGNI): Lighthouse CI budgets, unit tests for the
player. They earn their place if the site grows.

---

## 7. Phasing

**Phase 1 — vertical slice.** The whole system, one post end to end.

1. Monorepo scaffold, npm workspaces
2. Agent at the post-1 stage (single `generateText` call) plus the trace
   recorder
3. Record the real traces for post 1
4. Astro site: design system, layout, `TracePlayer`, GitHub Pages deploy
5. Cover pipeline
6. Post 1 complete: `index.mdx`, `linkedin.md`, `cover.png`, `cover-prompt.md`
7. Live at `baradelli.github.io/nine-commits`

**Phase 2 onward.** One post at a time. Every subsequent post reuses the rails
built in phase 1: advance the agent, record traces, write the post, generate
the cover, tag the commit.

## 8. Decisions log

| Decision | Choice | Why |
|---|---|---|
| Blog goal | Personal brand / authority | Author's stated objective |
| Immersion style | Deterministic simulations + animated explainers | No API keys, no cost, always works; visual explainers carry the narrative |
| Topic split | Narrative arc, one agent built across posts | Differentiates from the course's structure |
| Authoring source of truth | The repository (MDX) | Text and simulation belong in the same commit; no Obsidian sync pipeline to maintain |
| Stack | Astro + MDX + Preact islands | Zero JS by default; interactivity only where it exists |
| Repo shape | Monorepo (`agent/` + `site/`) | Reader can read the code that produced the demo they just ran |
| Course code reuse | Own implementation, attributed | Source repo is unlicensed; copying it would undermine the credibility the project exists to build |
| URL | `baradelli.github.io/nine-commits` | Keeps the user site free for a future personal homepage |
| Series name | Nine Commits | Concrete, binds post to commit |
